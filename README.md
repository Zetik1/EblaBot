# Бот-модератор для чата друзей

Telegram-бот на aiogram 3 для закрытой супергруппы с друзьями. Это инструмент в руках админов и модераторов, а не автономный «бан-бот»: он приветствует новичков, помогает тегать нужных людей, помнит дни рождения и даёт модераторам удобные команды.

> **Статус:** в разработке. Ниже описана целевая функциональность.

## Запуск каркаса

Нужен Python 3.12. Команды выполнять из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` указать токен своего тестового бота, свой Telegram ID и ID тестовой
супергруппы. Затем запустить:

```powershell
.\.venv\Scripts\python.exe main.py
```

На Linux/macOS использовать `.venv/bin/python` и `cp .env.example .env`.
Команда `/ping` в личке отвечает `pong`. Остальные функции ниже пока запланированы.
Остановка — Ctrl+C. При одновременной разработке использовать разные тестовые
токены: два polling-процесса с одним токеном конфликтуют.

### Куда добавлять свою часть

- Обработчики — отдельными модулями в `handlers/`, подключение роутера — в
  `handlers/__init__.py`. Минимальный пример — `handlers/health.py`.
  Для групповых команд явно проверять `settings.group_id`: конфигурация сама
  по себе не ограничивает доступ и не выдаёт роли.
- Модели — в `db/models/`, наследовать от `db.base.Base` и импортировать в
  `db/models/__init__.py`, чтобы они участвовали в создании таблиц.
- Логику функций — в `services/`, клавиатуры — в `keyboards/`, по мере необходимости.
- В обработчик можно добавить аргументы `settings: Settings` и
  `session: AsyncSession`: их передаёт общий запуск. На каждое событие создаётся
  отдельная сессия; запись сохранять явно через `await session.commit()`.
  Несохранённые изменения откатываются при закрытии сессии, в том числе при ошибке.

База SQLite создаётся в `data/bot.sqlite3`. Пока моделей нет, она пустая.
Создание таблиц на старте не изменяет структуру уже существующих таблиц: при
изменении модели отдельно согласовать перенос данных. Не удалять чужую БД.
Проверки каркаса без токена и подключения к Telegram:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Возможности

### Новые участники
- Приветствие в нужной теме и тег участников, чтобы с новичком поздоровались.
- Ссылка на личку бота, где человек заполняет данные о себе.
- Напоминание админам обновить список тегов.

### Роли и права
- Три уровня: админ, модератор, юзер.
- Владелец и админ Telegram автоматически получают роль админа в боте.
- Первый админ бота задаётся в конфиге.
- Метки (города, интересы) и часовой пояс не связаны с уровнем прав: это отдельные сущности.

### Ручная модерация
- Мут, кик, бан и обратные действия командами.
- Запросы на модерацию: юзер подаёт запрос командой, модератор или админ одобряет или отклоняет кнопкой (свой запрос одобрить нельзя, запросы на бан одобряет только админ).
- Шуточный бан: мут на срок от 30 секунд до 1 минуты с торжественным объявлением. На владельца и админа Telegram бот не может наложить ограничение, поэтому для них это только объявление о посягательство на суверенитет его величества админа.

### Метки и теги
- Метки: города, интересы и любые другие. Часть меток человек берёт себе сам кнопками, часть (например, модератор) выдают только админы; модераторы могут создавать метки без привилегий.
- Тег всех или по метке, с привязкой к сообщению (ответом) или без.
- Упоминание людей без username.
- Админы могут вручную пополнять список для тегов.

### Защита от лишних тегов
- Кулдаун 5 секунд: быстрые повторы молча игнорируются.
- Повторный тег в течение 2 минут требует подтверждения. Пока подтверждение висит, новые попытки игнорируются; при перезапуске бота ожидающие подтверждения сбрасываются.
- Тег в другой теме повтором не считается. Правила действуют на всех внутри правово-ролевой системы бота.

### «Не беспокоить»
- Человек включает режим для себя командой: причина текстом, срок в днях.
- Пометка появляется сразу, а после каждого тега бот перечисляет, кого не тегнул.
- Админы бота режим не обходят.

### Дни рождения
- Человек сам задаёт свой день рождения и часовой пояс; админы могут задать чужие.
- День рождения считается по часовому поясу самого человека.
- В личке бота: три ближайших дня рождения и общий список.
- Напоминание в личку за 2–3 дня и публичный тег в день рождения в отдельной теме.
- Можно отказаться от тега: тогда нет ни публичного тега, ни напоминаний другим, но в списке человек остаётся.
- 29 февраля день лохов, а поэтому не учитывается при составлении списков напоминаний (сложна, потом придумаю че делать).
- Если бот был недоступен, пропущенные события не догоняются; вместо этого формируется читаемый отчёт о пропущенном.

### Развлечения
- Триггер-фразы с шуточными ответами.
- Рандомайзер: выбор людей (из всех или по метке), числа в диапазоне, монетка.
- Дуэль «русская рулетка»: только по согласию через кнопку (есть и кнопка отказа). Проигравший исключается из чата и может вернуться через личку бота. Увидит ли он прежнюю историю, зависит от настройки группы «история для новых участников».

### Если человек не запускал бота
Функциональность ограничена как для него самого, так и в отношении него (кроме модераторских команд). Бот не падает, если в личку не достучаться.

## Права по ролям

| Действие | Админ | Модер | Юзер |
|---|---|---|---|
| Теги и свои настройки (ДР, пояс, «не беспокоить», свои метки) | да | да | да |
| Шуточный бан | да | да | нет |
| Мут и кик | да | да (только на юзеров) | запрос |
| Бан | да | запрос | нет |
| Одобрение запросов | мут, кик, бан | мут, кик | нет |
| Создание меток без прав | да | да | нет |
| Выдача привилегированных ролей, принудительная выдача меток, правка чужих ДР и поясов, пополнение списка тегов, настройки бота | да | нет | нет |

## Ограничения Telegram, которые стоит знать

- Бот не может ограничить владельца и админов чата, заданных через физический функционал Telegram.
- Бот может написать в личку только тому, кто запускал его (`/start`).
- События о входе и выходе участников приходят, только если бот админ чата и нужные типы указаны в `allowed_updates`.
- Ограничение через `until_date` короче 30 секунд или длиннее 366 дней Telegram считает вечным.

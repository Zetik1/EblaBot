# Roadmap: бот-модератор для друзей (aiogram 3)

*Составлено 2 ноября 2026. Стек: Python, aiogram 3.x, SQLite + SQLAlchemy 2.0 (async, драйвер aiosqlite), pydantic-settings, .env.*

## Как пользоваться

Иди по этапам по порядку: каждый заканчивается работающим ботом. ☐ — задачи, **Где искать** — разделы документации и ключевые слова для поиска, **Готово, когда** — критерий завершения, **Грабли** — известные ловушки. Названия разделов в документациях могут слегка отличаться, ищи по ключевым словам.

Основные источники: docs.aiogram.dev (ветка 3.x), core.telegram.org/bots/api, core.telegram.org/bots/features, core.telegram.org/bots/faq, docs.sqlalchemy.org (2.0), docs.python.org.

## Принятые решения

- Три уровня прав: админ, модератор, юзер. Владелец и админ Telegram автоматически админы бота, первый админ задаётся из .env. Роли бота важнее ролей Telegram.
- Уровень прав (один), метки для тегов (много) и часовой пояс (один, свойство человека) — три разные сущности.
- Бот не может ограничить владельца и админа Telegram: шуточный бан на них — только объявление. Правила самого бота (кулдаун, подтверждение, «не беспокоить») действуют на всех.
- Люди, не запустившие бота, получают урезанный функционал (кроме модераторских команд); бот не падает, если в личку не достучаться.
- Идентификаторы тем (топиков) задаются в конфиге.
- Отложено: цитата дня, рейтинг позора, реакции по условиям (например, «молчал 4 дня»). Опрос «кто идёт» снят.

Таблица прав (согласована):

| Действие | Админ | Модер | Юзер |
| --- | --- | --- | --- |
| Теги и свои настройки (ДР, пояс, «не беспокоить», свои метки) | да | да | да |
| Шуточный бан | да | да | нет |
| Мут и кик | да | да (только на юзеров) | запрос |
| Бан | да | запрос | нет |
| Одобрение запросов | мут и кик, бан | мут и кик | нет |
| Создание меток без прав | да | да | нет |
| Выдача привилегированных ролей, принудительная выдача меток, правка чужих ДР и поясов, пополнение списка тегов, настройки бота | да | нет | нет |

Свой запрос одобрить нельзя. Запросы на бан одобряет только админ.

## Этап 0. Подготовка

- ☐ Тестовая супергруппа с включёнными темами (топиками); бот в ней админ с правами ограничивать участников и приглашать
- ☐ Отдельный тестовый бот (свой токен) и второй аккаунт Telegram для проверок; боевой бот — позже
- ☐ Python, venv, Git; первым коммитом .gitignore; затем .env и .env.example (токен, твой id, id группы и тем, путь к БД)
- ☐ Зависимости: aiogram, sqlalchemy, aiosqlite, pydantic-settings; список в requirements.txt

**Где искать:** aiogram — Installation (требуемая версия Python); pydantic-settings (класс настроек BaseSettings, чтение из .env, тип SecretStr для токена, чтобы он не попадал в логи); Python venv.

**Грабли:** токен, попавший в репозиторий, нужно перевыпускать в BotFather (команда /revoke).

**Готово, когда:** токен читается из .env, git status не показывает .env.

## Этап 1. Скелет

- ☐ Структура: main, config, handlers/, middlewares/, db/, services/, keyboards/
- ☐ Логирование, Bot + Dispatcher, polling, /start в личке, ответ на команду в группе (в той же теме)
- ☐ Сразу задать allowed\_updates: сообщения, callback\_query, chat\_member, my\_chat\_member

**Где искать:** aiogram — Router, Dispatcher, polling, Command filter, Magic filter (F); Python logging HOWTO; Bot API — message\_thread\_id.

**Грабли:** два polling-процесса на одном токене конфликтуют, не запускай локально и на сервере одновременно; в теме General при отправке не указывай message\_thread\_id=1: по опыту других проектов Telegram отвечает ошибкой «message thread not found»; входящие оттуда могут приходить без message\_thread\_id. Подтверди на тестовой группе.

**Готово, когда:** бот отвечает в личке и в теме группы, логи пишутся.

## Этап 2. Хранилище и люди

- ☐ Сначала отдельный скрипт-песочница: Person, Label, связь многие-ко-многим; добавить, выбрать, перезапустить
- ☐ Модели: человек (id Telegram, имя, username — может быть пустым, роль, пояс, ДР, отказ от тега ДР, «не беспокоить» до какого момента и причина, достижим ли в личке), метка (название, можно ли брать самому), связь человек–метка
- ☐ Движок, сессия на одно событие (через middleware), создание таблиц на старте
- ☐ Регистрация при /start и при входе в группу; ты — админ по id из .env

**Где искать:** SQLAlchemy 2.0 — ORM Quick Start, Declarative Mapping (Mapped, mapped\_column), Asynchronous I/O (asyncio), Many to Many, SQLite dialect (Foreign Key Support, DateTime и часовые пояса); aiogram — Middlewares.

**Грабли:** expire\_on\_commit в async; ленивая загрузка связей в async не работает (ищи selectinload); внешние ключи в SQLite включаются отдельно; SQLite не хранит пояс, поэтому всё время в UTC, а пояс человека как название зоны.

**Готово, когда:** после перезапуска бот помнит людей и их роли.

## Этап 3. Роли

- ☐ Перечисление ролей; проверка роли перед командой (фильтр или middleware)
- ☐ Синхронизация владельца и админов Telegram в админы бота (при старте и при повышении)
- ☐ Команды выдачи и снятия роли модератора; правило: модер не действует на модера и админа
- ☐ Решить: что делать с ролью в боте, если человека сняли с админов Telegram

**Где искать:** aiogram — Writing your own filter, Middlewares, ChatMemberUpdated filter (PROMOTED\_TRANSITION); Bot API — getChatAdministrators, getChatMember, типы ChatMember\*.

**Готово, когда:** команда «только для админов» не срабатывает у юзера, админ Telegram получает роль в боте.

## Этап 4. Новые участники

- ☐ Событие входа: приветствие и тег участников с сообщением о новичке, чтобы поздоровались
- ☐ Сообщение со ссылкой на личку бота («настрой профиль») и напоминание админам обновить список тегов

**Где искать:** aiogram — ChatMemberUpdated filter (JOIN\_TRANSITION), Utils: Deep Linking (create\_start\_link), CommandStart с параметром deep link, Utils: Formatting (TextMention); Telegram — Deep linking (допустимые символы и длина параметра).

**Грабли:** события chat\_member приходят, только если бот админ и тип указан в allowed\_updates; проверяй вход, выход и повторный вход вторым аккаунтом.

**Готово, когда:** второй аккаунт заходит, и бот реагирует в нужной теме.

## Этап 5. Ручная модерация

- ☐ Мут и размут, кик (бан + разбан), бан и разбан; цель по ответу на сообщение или по указанию
- ☐ Запрос на модерацию: команда, сообщение с кнопками «одобрить» и «отклонить», правила одобрения по таблице прав
- ☐ Шуточный бан: мут на срок от 30 секунд до 1 минуты (параметр команды) и объявление; для владельца и админа Telegram — только объявление

**Где искать:** Bot API — restrictChatMember (параметр until\_date: ограничение снимется само в указанный момент, планировщик для шуточного бана не нужен; допустимо от 30 секунд до 366 дней, иначе ограничение считается вечным; aiogram принимает datetime, timedelta или число), ChatPermissions, banChatMember, unbanChatMember; aiogram — CallbackData factory, обработка callback\_query, Exceptions.

**Грабли:** callback\_data не длиннее 64 байт; на callback нужно отвечать; бот не может ограничить владельца и чужих админов; у бота должны быть права; срок шуточного бана в 30 секунд лежит ровно на границе until\_date: если к приходу запроса до конца мута останется меньше 30 секунд, Telegram сделает его вечным, поэтому закладывай запас в несколько секунд и проверь на тесте, что мут снимается.

**Готово, когда:** запрос юзера проходит весь цикл до одобрения модером, шуточный мут снимается сам.

## Этап 6. Метки и теги

- ☐ Метки: создание (модер, админ), самовыдача кнопками, принудительная выдача админом
- ☐ Тег всех и по метке, с привязкой к сообщению (ответом) и без; админ может пополнять список
- ☐ Люди без username: упоминание по id; длинные списки несколькими сообщениями

**Где искать:** aiogram — Keyboard builder, CallbackData factory, Utils: Formatting (TextMention); Bot API — MessageEntity (лимиты); Bots FAQ — лимиты отправки сообщений.

**Готово, когда:** тег по метке упоминает всех нужных, включая людей без username.

## Этап 7. Защита тегов и «не беспокоить»

- ☐ Кулдаун 5 секунд на человека и тему: тег молча игнорируется
- ☐ Повторный тег в течение 2 минут: подтверждение «уверен?»; пока оно висит, новые попытки игнорируются; живёт до конца окна, при рестарте сбрасывается; для всех
- ☐ «Не беспокоить»: команда с причиной и сроком в днях, пометка сразу, список нетегнутых после тега, админы не обходят
- ☐ Подумать: нужен ли планировщик для снятия режима или хватит проверки в момент тега

**Где искать:** Python — time.monotonic, datetime, основы asyncio; aiogram — CallbackData, Finite State Machine (чтобы понять, чем оно отличается от хранения в обычной памяти).

**Готово, когда:** двойной клик не плодит теги, подтверждение работает, пропущенные из-за режима видны.

## Этап 8. Дни рождения и время

- ☐ Команды: свои ДР и пояс — сам; чужие — админы; 29 февраля только в високосные годы (проверка даты не должна падать)
- ☐ Список ближайших трёх и общий — в личке бота
- ☐ Планировщик: напоминание за 2–3 дня в личку и тег в день ДР в нужной теме, по поясу именинника
- ☐ Отказ от тега: ни публичного тега, ни напоминаний другим; в списке человек остаётся
- ☐ Журнал отправленного (защита от дублей); при простое пропущенное не догоняется, читаемый отчёт уходит админам или в тему
- ☐ Решить: во сколько по местному времени слать напоминания и поздравления

**Где искать:** APScheduler 3.11.x (AsyncIOScheduler; ветка 4.x всё ещё в альфа-версии, её не берём) или свой цикл на asyncio; Python — zoneinfo, datetime (aware и naive); SQLAlchemy — DateTime и SQLite; aiogram — Exceptions (TelegramForbiddenError); my\_chat\_member для приватных чатов.

**Грабли:** на Windows для zoneinfo нужен пакет tzdata; одно и то же событие не должно сработать дважды.

**Готово, когда:** ДР, поставленный «на через минуту», срабатывает ровно один раз, после перезапуска дубликатов нет.

## Этап 9. Веселье и недоступность лички

- ☐ Триггер-фразы
- ☐ Рандомайзер: люди (по метке или из всех), число в диапазоне, монетка
- ☐ Дуэль: вызов с кнопками «принять» и «отказаться», оба достижимы в личке; исход, кик проигравшего, ссылка для возвращения в личку
- ☐ Ограничения для не запустивших бота и общий обработчик ошибок отправки в личку; решить, куда бот сообщает о неудаче

**Где искать:** aiogram — Magic filter; Python — random; Bot API — createChatInviteLink, unbanChatMember; настройки группы — видимость истории для новых участников.

**Грабли:** вернувшийся участник увидит прежнюю историю, только если она открыта для новых участников.

**Готово, когда:** дуэль корректно проходит согласие, отказ и недоступность лички без падений.

## Этап 10. Выпуск

- ☐ Хостинг (VPS или домашний сервер), боевой токен, .env на сервере
- ☐ Автозапуск и перезапуск при падении (systemd или Docker)
- ☐ Резервные копии БД и ротация логов
- ☐ Уведомление админам при старте бота, чтобы замечать перезапуски

**Где искать:** документация systemd (unit-файлы) или Docker; SQLite — Backup API, VACUUM INTO, режим WAL; Python — logging.handlers.RotatingFileHandler.

**Грабли:** не копировать файл БД вживую во время записи; один polling на токен.

**Готово, когда:** бот сам поднялся после перезагрузки сервера, копию БД удалось восстановить.

## Правила пути

- Один этап за раз; коммит после каждого рабочего шага.
- Проверяй вторым аккаунтом.
- Обработку ошибок отправки в личку делай с первого этапа.
- Застрял — приноси код или текст ошибки, разберёмся вместе без готовых решений.

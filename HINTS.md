# #17 — Роль владельца при /start

1. Начни с [`handlers/start.py`](handlers/start.py). Сравни ID отправителя с `settings.owner_id`. `OWNER_ID` в `.env` задаёт Telegram ID владельца бота.
2. Открой [`services/people.py`](services/people.py). `upsert` создаёт профиль при первом сохранении и обновляет его при совпадении Telegram ID. Посмотри, где задаются значения для этих двух случаев. Как сделать, чтобы у владельца записался `admin`, а у остальных сохранилась текущая роль?
3. Возьми за образец [`tests/test_start_flow.py`](tests/test_start_flow.py) и [`tests/test_roles.py`](tests/test_roles.py). После `/start` прочитай роль в новой сессии. Проверь чистую базу и профиль владельца, который уже был записан с `user`.

Пример: `OWNER_ID=42`, профиль 42 уже есть с `user` → после двух `/start` у него одна строка с `admin`. У другого человека с ролью `moderator` обновление имени сохраняет `moderator`.

К PR приложи скриншот проверок. Перед открытием PR убери этот файл из своей ветки.

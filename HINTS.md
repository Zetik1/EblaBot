# #17 — Роль владельца при /start

Когда владелец пишет боту `/start` в личку, его профиль должен сохраниться с ролью `admin`. Если профиль уже есть, обнови ту же запись.

1. Создай `services/roles.py` для правил работы с ролями. Начни с функции `role_for_registration(telegram_id, owner_id)`. Она получает Telegram ID отправителя и ID владельца из `OWNER_ID`. Для владельца она возвращает `admin`, для остальных — `None`. Здесь `None` означает, что при сохранении профиля роль не нужно задавать.
2. В [`services/people.py`](services/people.py) добавь `register_person()`. Передай в неё сессию, данные профиля и `owner_id`. Внутри вызови `role_for_registration()` и передай результат в `save_person()`.
3. В `save_person()` добавь необязательный аргумент `role`. В запросе `values(...)` задаёт поля новой записи, а `set_` в `on_conflict_do_update(...)` задаёт поля для обновления существующей. Добавляй явно переданную роль в обе части. Если роль не задана, новый профиль получит `user` по умолчанию, а существующий сохранит свою роль.
4. В [`handlers/start.py`](handlers/start.py) добавь `settings: Settings` в параметры `start()`. `Dispatcher` уже передаёт настройки. Возьми ID и данные профиля из `message.from_user`, передай их и `settings.owner_id` в `register_person()` и отправь приветствие после успешного сохранения.

Возьми за образец [`tests/test_start_flow.py`](tests/test_start_flow.py) и [`tests/test_roles.py`](tests/test_roles.py). Отправь `/start` через `Dispatcher` и прочитай результат из временной SQLite в новой сессии. Проверь такие случаи.

- Новый владелец отправляет `/start` → появляется одна запись с `admin`.
- `OWNER_ID=42`, профиль 42 уже записан с ролью `user` → после двух `/start` у 42 одна запись с `admin`.
- Другой человек впервые отправляет `/start` → получает `user`. Если у него уже есть профиль с ролью `moderator`, `/start` с новым именем обновляет имя и сохраняет `moderator`.

Приложи к PR скриншот запуска проверок с результатом и покажи, где в тесте после `/start` читается сохранённая роль. Перед открытием PR убери `HINTS.md` из своей ветки.

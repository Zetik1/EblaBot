# #20 — Проверка обновления SQLite в Docker

Открой задачу #20 и держи эту подсказку рядом. Все команды запуска выполняй в отдельной копии `EblaBot-upgrade-check`, как описано в задаче. Если токен тестового бота общий, договорись об очереди запуска.

1. Посмотри в [`compose.yaml`](compose.yaml) строку `./data:/app/data`. Docker показывает одну и ту же папку с двух сторон. В Windows файл лежит в `data/bot.sqlite3`, внутри контейнера — в `/app/data/bot.sqlite3`. Поэтому после остановки контейнеров файл остаётся на компьютере.
2. На старой версии `0b7d499` сначала отправь `/start`. Убедись, что в таблице есть профиль. Затем останови копию и переключись на `9b5d5fb` в той же папке, сохранив `data`.
3. После обновления первым делом прочитай таблицу. Отложи новый `/start` до окончания проверки, иначе можно случайно создать строку заново и пропустить потерю данных.

Пример: до обновления в таблице одна строка с твоим именем. После обновления строка та же, плюс `user`. После повторного запуска она по-прежнему одна.

Подготовь три скриншота строк до обновления, после обновления и после перезапуска. Закрой Telegram ID и username. Для этой проверки достаточно скриншотов.
